# 池袋・クライアント指摘対応状況

最終更新: 2026年8月15日

対象: 池袋・現場確認環境

判定: **現場確認開始は最新版の反映・技術確認後／正式本番切替はNo-Go**

この文書は、クライアントから受け取った指摘を「修正済み」「現場確認」「仕様・移行データ待ち」に分けたものです。「修正済み」はコード上の対応状況であり、最新版が確認環境へ反映済みであることを意味しません。最新版のCI、確認環境への反映、backup隔離復元、主要URLのブラウザ確認が完了したと移行担当者から連絡されるまでは、現場確認を開始しません。技術試験の合格だけで、操作性、会計結果、旧システムとの業務同等性を承認済みとは扱いません。現場確認は[池袋・新システム 現場確認マニュアル](./IKEBUKURO_FIELD_UAT_MANUAL.md)に沿って記録します。

## 正式本番切替を止める残件

次が確定・移行・現場承認されるまで、本番切替は行いません。

- 旧入金・精算履歴、旧入金種別、控除、保証、バック率
- 旧同等の部分精算、取消・反転、印刷、出金の運用仕様
- 2026年8月1日より前の出勤を使う過去日報と、5時30分の日界
- 姫予約の媒体対応表
- 手取り・店舗売上の正式配分規則
- 旧予約状態とランクの変換規則
- 旧ポイント履歴、NG履歴、予約変更履歴、旧チャットの保存・参照方針
- 旧会員13,312行の電話番号について、有効13,239件、形式不正71件、空欄2件を正式にどう扱うか、および同一番号11組（22行）の統合・例外方針
- 現場担当者によるチェックリスト完了と署名

### 正式本番切替の必須ゲート

次をすべて記録し、現場確認者と責任者の双方がGoを出すまでは、正式本番切替は**No-Go**です。

1. 旧本番の書込みを停止し、停止時刻を固定する。
2. 旧本番の最新DB、共有会員DBの締切時点、前回以降の画像差分を同じ基準時刻で取得・固定する。
3. 新システム側の直前DBを暗号化backupし、別環境への隔離復元に成功する。
4. 空DBへschema18として検証付き取込を行い、Prisma migrationが18件適用済みであることを確認する。
5. 全顧客に必要な`CustomerStoreAssignment`があり、孤立割当0件、予約店舗との不一致0件であることを確認する。
6. 旧データから移行した顧客について、正式運用に必要なプロフィール項目が欠損していないことを確認する。名前だけ登録の`NULL`許容は新規受付の仕様であり、旧顧客欠損の補完規則には流用しない。
7. 全modelの件数、業務集計、参照整合性、画像件数とSHA-256を、固定した取込元と突合する。
8. health check、公開・管理主要URL、認証、予約導線のブラウザsmokeを通し、現場チェックリスト署名と責任者Goを得る。
9. 切替後の監視期間が終わるまで旧本番を変更・破棄せず、直前backupから戻せるロールバック手順と判断者を確保する。

旧本番はこのゲートを満たす正式切替まで変更しません。確認環境への反映や現場確認は、正式本番切替の承認を意味しません。

- 電話番号起点の顧客登録回帰で、国内・国際表記、池袋固定、番号引継ぎ、名前だけ登録、`NULL`保存、重複防止を確認する。
- 顧客店舗割当、権限、機密項目、店舗切替時の古い検索結果、予約・チャットの店舗分離を回帰確認する。
- 最新版でPrettier、ESLint、TypeScript、全テスト、coverage、production build、Playwrightを完走する。
- 確認環境の直前暗号化backupを隔離復元し、18件のmigrationと店舗割当の不変条件を確認する。
- 最新版を確認環境へ反映した後、公開導線、管理者認証、顧客、予約、キャスト、画像をブラウザで確認する。

テスト件数、リリースSHA、反映時刻、backup、隔離復元、ブラウザ確認の実測結果は、実行完了後のリリース記録を正とします。過去のテスト件数を最新版の結果として流用しません。これらが完了しても、現場での操作性と業務上の計算結果は、別途チェックリストで承認します。
