# UI Proposals

作成日: 2026-07-04

この文書は `ui-improvement-instructions.md` Phase U8 の提案のみ項目をまとめたものです。予約仕様、法務判断、画像最適化、E2E 基盤導入など、今回の UI 修正では実装しない判断事項を扱います。

## 予約フローのステップ順見直し

現状の予約フローは時間選択がコース選択より先に出るため、後からコースを変えると選択済み時間が無効になる可能性があります。仕様変更として進める場合は、コース選択を先に置き、所要時間が確定してから空き枠を表示する順序に変えるのが自然です。

実装前に確認すべき点:

- 指名キャストなし予約でもコース先行にするか
- コース未選択時に最短コースで空き枠を仮表示する必要があるか
- 既存の予約 URL パラメータとの互換性

## 予約成功後の再送信防止

現在は成功トーストとインライン表示で完了を伝えています。二重送信をさらに防ぐなら、予約完了ページへ遷移し、ブラウザ戻る時の再送信や同一入力の連続送信をサーバー側でも拒否する設計が必要です。

候補:

- `/[store]/booking/complete` を追加して完了情報を表示する
- 予約作成時に idempotency key を発行する
- 顧客マイページの予約詳細へ誘導する

## 年齢確認ゲート

年齢確認は法務・運用判断が必要です。導入する場合は、対象ページ、確認の有効期限、離脱先、Cookie/localStorage の保存期間を決める必要があります。

推奨の検討単位:

- 店舗トップ以下の公開ページ全体を対象にするか
- 予約ページだけ厳格化するか
- 未確認時の離脱先を検索エンジン向けにどう扱うか

## ダークモード方針

`components/theme-provider.tsx` は存在しますが、アプリ全体のテーマ切替は未配線です。luxury テーマはダーク前提のため、無理にライト/ダーク切替を入れるより、管理画面だけに対象を絞るか、未使用の provider を削除するかを決める必要があります。

## `next/image` 移行

画像は現在 `<img>` と `images.unoptimized: true` を前提にしています。`next/image` へ移行するとパフォーマンス改善が見込めますが、Supabase/外部画像ドメイン、既存保存 URL、レスポンシブ切り抜きの検証コストが高いため、別タスクで扱うべきです。

進める場合は、店舗トップのヒーロー、キャストカード、バナーの順に移行し、画像が欠けないことを 375px/1280px で確認します。

## メタデータ完全化

client page では `metadata` を直接 export できないため、完全対応には薄い server `page.tsx` と client 子コンポーネントへの分離が必要です。今回は layout と server page の範囲に留めました。

次に進める候補:

- admin dashboard
- admin customers
- admin analytics 主要ページ
- cast portal dashboard

## E2E テスト

UI 回帰を自動で検出する仕組みはまだありません。Playwright を導入する場合は、最初から全画面を対象にせず、次の代表フローだけに絞るのが現実的です。

- 店舗トップからキャスト一覧、予約ページへ移動
- 未ログイン予約からログイン後 callbackUrl で戻る
- 管理者ログイン後、設定保存でトーストが出る
- 予約編集ダイアログで未保存変更の破棄確認が出る

導入前に CI 実行時間、テスト用認証情報、DB/モックデータの供給方法を決める必要があります。
