## 1. 確認前に読むこと

この環境は、旧システムの池袋データをコピーした**画面・操作確認専用**です。本番業務には使用しません。旧システムは現在も本番として動いています。

- V5確認候補データの基準日時: **2026年8月14日 19:31:10（日本時間）**
- 公開HP: <https://salon.c-platinum.com/ikebukuro>
- 管理画面: <https://salon.c-platinum.com/admin/login>
- 管理者・顧客・キャストのメールアドレスとパスワードは、移行担当者から別に受け取ってください。
- V5取込後の期待件数は、顧客13,313件、予約2,122件、出勤241件、キャスト35名、公開画像105枚です。

V5のsnapshot・画像105枚・変換後全model件数・全field SHA-256・Prisma migration 16件は、DBへ接続しないローカル検証に合格しています。V5のリモート取込、取込後DB突合、ブラウザ確認は別工程です。現場確認は、移行担当者から「V5取込後突合が完了した」と連絡を受け、画面の件数が上記V5期待値と一致してから開始してください。

2026年7月28日のV4については、更新前backup、空DB・storage再作成、取込、全件突合、移行後backup復元まで完了した履歴があります。V4の件数（顧客13,227件、予約1,049件、出勤210件、キャスト38名、公開画像112枚）を、今回確認するV5の期待値と取り違えないでください。

公開HPの年齢確認、顧客ログイン、キャストログインはまだ現場確認前です。このマニュアルですべて確認し、結果を移行担当者へ返してください。

### `[確認用]` の意味

顧客名などの先頭にある `[確認用]` は不具合ではありません。旧データを確認用にコピーし、実顧客と間違えないように付けた印です。コピー済みの `[確認用]` 顧客・予約・キャストは変更・削除しません。

V5では顧客台帳を確認できるようにしていますが、次の制約があります。

- 予約は2026年1月1日以降だけです。全期間の予約履歴ではありません。
- ポイントは現在残高だけで、増減履歴はありません。
- NG設定・NG履歴は移行していません。
- 確認用ログインへ割り当てたQA顧客で確認できる完了予約は15件です。
- 旧会員行の生年月日4件、登録日時71件、電話番号65件と、参照先台帳がない顧客1件は、旧値の不足・重複により確認用の補完値を含みます。
- メールアドレスは旧値に無効・欠損が多く、確認環境専用の無効アドレスへ補完したものがあります。
- フリガナ専用の旧項目がないため、`nameKana` は多くの顧客で氏名をそのままコピーしています。

これらの補完値を、旧システムの正しい値として承認しないでください。

### やってはいけないこと

- 実在するお客様の氏名、電話番号、メールアドレス、住所を入力しない。
- 指定された保護接続の外から管理画面・顧客画面を開かない。
- 表示された旧顧客情報をコピー、ダウンロード、画面録画、共有しない。
- 実際の予約、会計、ポイント処理として使用しない。
- 電話、LINE、SMS、メールを送信しない。実カードで決済しない。
- コピー済みの `[確認用]` データでは、保存、削除、状態変更、予約確定、キャンセル確定を押さない。
- 書込み操作は、移行担当者から「外部送信停止を確認済み」と連絡を受けた後、このマニュアルで新しく作る `[UAT]` 専用データだけで行う。
- 旧システムを停止・変更しない。

### 4-5. `[UAT]` 専用データで予約操作を確認

この項目だけは実際に保存します。LINE・メール・SMS・Push・決済の外部送信が停止していることを、移行担当者が先に確認してから始めます。コピー済みデータは選ばず、ここで新規作成するものだけを使います。

1. 確認を始める現在時刻を、月日4桁と時分4桁で控えます。例: 8月15日10時30分なら `0815` と `1030` です。
2. ダッシュボードの「新規顧客登録」から、次の架空情報だけで顧客を作ります。
   - 名前: `[UAT] 予約確認 0815-1030`（数字は実際の月日・時分へ置換）
   - 電話番号: `000` + 月日4桁 + 時分4桁。例: `00008151030`
   - メールアドレス: 空欄
3. 登録後、その電話番号をダッシュボードへ直接入力して検索し、作成した顧客だけが表示されることを確認します。
4. 「この顧客で予約を取る」または目立つ位置の「予約作成」から、未来日の空き枠を30分単位で選びます。出勤中のキャスト、コース、オプションを選び、支払方法はカード、カード管理番号は `UAT-0815-1030` のような架空番号にします。カード番号は入力しません。
5. 予約を確定し、予約一覧とタイムラインの両方に、`[UAT]` 顧客名、キャスト、時刻、コース、オプション、料金、カード管理番号が残ることを確認します。
6. 作った予約だけを開き、時刻を30分変更し、指名区分または担当キャストを変更して保存します。再度開いて、変更内容が残ることを確認します。
7. 作った予約だけをキャンセルし、キャンセル理由へ `[UAT] 動作確認のため取消` と入力します。確定後、稼働中の予約・タイムラインから消え、キャンセル済みを表示する一覧では理由と状態を確認できることを確かめます。
8. 新規顧客→予約→変更→キャンセルまで完了した顧客IDと予約IDを、不具合メモへ記録します。移行担当者が確認終了後に `[UAT]` データだけを整理します。

- [ ] 前回の入力文字が残らず、新規顧客と新規予約を登録できた。
- [ ] 電話番号の直接検索と顧客詳細への移動ができた。
- [ ] 空き枠、30分単位、フィルター、コース順、オプション選択が正しく動いた。
